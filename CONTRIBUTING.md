# Contributing

Open an issue for a reproducible bug or a focused improvement. For a substantial
redesign, discuss the scope before spending time on it. Fork the repository,
work on a branch and submit a pull request with the reason and actual validation.

Original code contributions use this repository's MIT license. Preserve notices
for adapted code. Keep asset contributions separate and state their creator,
source, license and modifications; do not assume a workshop download permits
redistribution on GitHub. Do not include credentials, private logs, engine
binaries, paid source recordings or assets without redistribution permission.

Use native s&box testing for gameplay changes. State the engine version and
whether you tested hosting, joining and the remote view. A compiler check does
not prove animation quality or Internet multiplayer reliability. Do not save
temporary review/input-injection components into playable scenes.

The maintainer decides what is merged and released. Accepted work keeps author
credit; no prize, revenue share or automatic inclusion is promised. Contributors
can also maintain independent forks under the relevant licenses.

The issue templates and [community review process](docs/COMMUNITY_REVIEW.md)
provide a review trail. `community/registry.json` is empty until submissions are
actually accepted. A CODEOWNERS file requests review; it does not itself enforce
branch protection.
